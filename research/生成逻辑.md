## 需求分析

项目的输入：

- 口头语言：
  ```txt
  基础版："120平日式三居，老人和孩子住，预算25万
  ```

- 参考图上传（可选）

- 结构化表单输入（辅助）
  ```txt
  房间类型：  [客厅] [卧室] [厨房] [全屋]
  面积：      _____ 平方米
  风格偏好：  [日式] [北欧] [现代] [中式] [美式]
  居住成员：  [单身] [夫妻] [有小孩] [有老人]
  特殊需求：  [无障碍] [收纳优先] [采光优先]
  ```

项目的输出：

1.  1–3张 360° 可拖拽全景图

   - 上下左右 360° 自由旋转

2. 多视角效果图

   1. 高质量的jpg图像
   2. 类似设计公司的产出

3.  合规清单

   ```txt
   ┌──────────────────────────────────────────┐
   │ ✅ 主卧净高 2.8m，符合住宅规范（≥2.4m）  │
   │ ✅ 卫生间防水层设计符合标准              │
   │ ✅ 无障碍通道宽度 ≥900mm（含老人需求）   │
   │ ⚠️ 厨房排烟管道需现场确认接口位置        │
   │ ❌ 阳台栏杆高度建议调整至 1100mm         │
   └──────────────────────────────────────────┘
   ```

4. 材料清单：
   ```txt
   ┌──────────┬──────────────┬──────┬──────┬────────┐
   │ 类别     │ 材料名称      │ 规格 │ 用量 │ 单价   │
   ├──────────┼──────────────┼──────┼──────┼────────┤
   │ 地板     │ 实木复合地板  │ 12mm │ 120㎡│ 280/㎡ │
   │ 墙漆     │ 乳胶漆（白）  │ 5L桶 │ 8桶  │ 380/桶 │
   │ 瓷砖     │ 哑光仿石砖   │ 600x600│50㎡│ 150/㎡│
   │ 主材合计 │              │      │      │ 8.2万  │
   │ 人工合计 │              │      │      │ 3.8万  │
   │ **总计** │              │      │      │**12万**│
   └──────────┴──────────────┴──────┴──────┴────────┘
   ```

5. PDF方案书
   ```TXT
   封面
   ├── 项目名称 / 客户姓名 / 日期 / 工作室 Logo
   
   第一章：需求确认
   ├── 用户原始输入的结构化呈现
   └── AI 理解摘要（"我们理解您的需求是…"）
   
   第二章：设计方案
   ├── 4张效果图
   ├── 平面图
   └── 360°全景二维码
   
   第三章：合规说明
   └── 合规清单全文
   
   第四章：材料与报价
   └── BOM 明细表 + 总价
   ```

## 技术方案

bpy + Langchain

LANGchian, AI 调用链：

```txt
用户输入
（自然语言 + 可选参考图 + 表单）
        │
        ▼
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        STAGE 1：理解层
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        │
        ▼
【1. 描述 AI】
输入：原始用户输入 + 参考图（如有）
任务：
  - 补全模糊信息（"三居" → 主卧/次卧/儿童房 具体尺寸）
  - 推断隐含需求（"有老人" → 无障碍通道、防滑地板、插座高度）
  - 扩写风格细节（"日式" → 低矮家具、木质调、漫射光、榻榻米可选）
输出：{detailed_brief}，一段结构化自然语言，~500 tokens
        │
        ▼
【2. 划分 AI】
输入：{detailed_brief}
任务：
  - 切分房间列表（客厅、主卧、次卧、厨卫…）
  - 确定生成优先级（⚠️ 重要：有依赖关系的先生成，如公共走廊先于各房间）
  - 估算每个区域的复杂度（影响后续 token 分配）
输出：
  {
    "rooms": [
      { "id": "living_room", "priority": 1, "depends_on": [] },
      { "id": "master_bedroom", "priority": 2, "depends_on": ["living_room"] },
      ...
    ],
    "global_constraints": {
      "total_area": 120,
      "style": "japanese",
      "residents": ["elderly", "child"]
    }
  }
        │
        ▼
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        STAGE 2：结构化层
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        │
        ▼
【3. 结构化 AI】                    ┌──────────────────┐
输入：单个 room + global_constraints  │   资产库索引      │
任务：                               │  furniture/       │
  - 空间几何定义                      │    sofa_jp_001.blend│
  - 家具选型 → 映射到资产库 ID ←──────│    table_jp_003   │
  - 材质定义 → 映射到材质库 ID         │  materials/       │
  - 光源定义                          │    oak_floor_pbr  │
  - 语义标注（合规检查用）              └──────────────────┘
输出：{room_json}
  {
    "room_id": "living_room",
    "geometry": {
      "width": 4.5, "length": 6.0, "height": 2.8
    },
    "furniture": [
      {
        "asset_id": "sofa_jp_001",   ← 直接对应资产库文件名
        "position": [1.2, 0.0, 2.0],
        "rotation_z": 0,
        "semantic_tag": "seating"
      }
    ],
    "materials": {
      "floor": "oak_parquet_pbr",
      "wall_main": "shoji_white_latex",
      "ceiling": "white_matte"
    },
    "lighting": [
      { "type": "area", "position": [2.25, 2.6, 3.0],
        "size": 0.8, "energy": 600, "color": [1.0, 0.97, 0.9] }
    ],
    "compliance_params": {        ← 专门给合规检查用的字段
      "clear_height": 2.8,
      "corridor_width": 1.1,
      "window_sill_height": 0.9
    }
  }
        │
        ▼
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        STAGE 3：验证层（新增）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        │
        ▼
【3.5 合规校验 AI】
输入：{room_json}.compliance_params + 规范规则库
两层校验：

  层 A：规则引擎（确定性，快）
    净高 2.8 ≥ 2.4 ✅
    走廊宽 1.1 ≥ 0.9 ✅（老人需求）
    阳台栏杆高度 ← 如 JSON 里没填，标记 ⚠️

  层 B：LLM 语义审查（模糊判断）
    "老人居住 + 卫生间" → 检查是否有扶手语义标注
    "儿童房" → 检查插座高度标注、家具尖角提示

输出：
  {
    "pass": false,
    "issues": [
      { "level": "error", "field": "balcony_railing", 
        "msg": "栏杆高度未标注，建议≥1100mm" },
      { "level": "warning", "field": "kitchen_exhaust",
        "msg": "排烟管道接口需现场确认" }
    ],
    "compliance_report": [...]   ← 直接用于最终输出
  }
        │
        ├─── issues 存在 error 级别?
        │         │YES
        │         ▼
        │    修正 AI：针对 error 字段修改 {room_json}
        │    → 回到合规校验（最多重试 2 次）
        │         │
        │         ▼ 修正后的 room_json
        │
        ▼ （无 error 后继续）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        STAGE 4：代码生成层
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        │
        ▼
【4. bpy 代码生成 AI】
输入：
  - {room_json}（已通过合规校验）
  - {r_existing}（已有的累积代码上下文摘要，非全文）
  - Few-shot 示例（固定的高质量 bpy 模板）

⚠️ 关键设计：不直接传入完整 r_old，而是传"代码摘要"
  {
    "existing_objects": ["Floor_LivingRoom", "Wall_North", "Sofa_001"],
    "existing_collections": ["LivingRoom"],
    "last_cursor_position": "after furniture placement"
  }
  原因：避免上下文窗口爆炸，且 AI 只需知道"已有什么"而非"怎么写的"

生成的代码片段格式：
  # === LIVING ROOM: FURNITURE ===
  bpy.ops.wm.append(filepath="//assets/sofa_jp_001.blend/Object/Sofa_JP_001")
  obj = bpy.context.object
  obj.location = (1.2, 2.0, 0.0)
  obj.rotation_euler[2] = 0

        │
        ▼
【4.5 执行验证环（新增，关键）】

  Step 1：Blender Headless 执行代码片段
    subprocess.run(["blender", "--background", "--python", chunk.py])

  Step 2：解析 stdout / stderr
    ├── 无报错 → r := r_old + new_chunk ✅，继续下一区域
    └── 有报错 → 进入修复循环
              │
              ▼
         【Debug AI】
         输入：报错信息 + 出错代码片段
         任务：定位错误行，输出修复后的代码片段
         → 重新执行验证（最多重试 3 次）
              │
              └── 3次仍失败 → 降级处理
                  （用 Bounding Box 占位，记录到 warning log）

        │ 所有区域循环完毕
        ▼
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        STAGE 5：渲染增强层（新增）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        │
        ▼
【5a. 相机 AI（新增）】
输入：完整场景的物体坐标列表 + 房间尺寸
任务：
  - 计算 3-4 个最优拍摄视角（避免家具遮挡、展示空间层次）
  - 输出相机位置 + 焦距参数
  - 全景相机：强制放在房间几何中心，高度 1.5m

  {
    "cameras": [
      { "name": "hero_shot", "location": [4.5, 1.0, 1.5],
        "target": [0, 3.0, 1.0], "lens": 24 },
      { "name": "detail_shot", "location": [2.0, -0.5, 1.2],
        "target": [1.0, 2.0, 0.8], "lens": 50 },
      { "name": "panorama", "location": [2.25, 3.0, 1.5],
        "type": "equirectangular" }
    ]
  }

        │
        ▼
【5b. 整体 AI（你原有的 Step 5，扩充）】
输入：完整 {r_all} + 所有 room_json 的材质汇总
任务（更细化）：
  ① 补充 PBR 材质节点（Roughness / Metallic / Normal Map 路径）
  ② 添加 HDRI 环境光（根据风格选 warm_interior.hdr / daylight.hdr）
  ③ 配置 Cycles 渲染参数（采样数、降噪、色彩管理）
  ④ 添加后处理节点（Glare / Color Balance / Vignette）
输出：{r_final}（完整可执行的 bpy 脚本）

        │
        ▼
【5c. Blender Headless 批量渲染】
  - 按相机列表渲染多视角 EXR（高位深，后期空间大）
  - 全景相机渲染 equirectangular 6000×3000 PNG
  - 输出：raw_renders/

        │
        ▼
【5d. ControlNet 增强（效果图变好看的关键）】
  每张渲染图：
    Depth Map + Normal Map（Blender 同时输出 pass）
        ↓
    ControlNet (depth + normal) 
    + Style Prompt（"日式客厅,柔和自然光,木质暖调,室内设计摄影"）
    + IP-Adapter（输入用户参考图，风格迁移）
        ↓
    SDXL + Interior LoRA
        ↓
    高质量 JPG 效果图

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        STAGE 6：输出合成层
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        │
        ├── 全景图 → Pannellum.js 托管 → 生成可访问 URL + 二维码
        ├── 效果图 → 直接输出 JPG
        ├── 合规报告 ← 收集所有 Stage 3.5 的 compliance_report
        ├── BOM ← 从所有 room_json 的 materials + furniture 聚合
        │         × 单价数据库 = 报价表
        └── PDF Agent → WeasyPrint 合成方案书
```
