## 3. ⚠️ 12 个必须团队拍板的决策点

### 🔴 关键架构决策（影响后续 80% 工作）

#### 3.1 多 Agent 真做 vs 假做？

| 选项 | 实质 | Demo 效果 | 工程量 |
|---|---|---|---|
| A. 真多 Agent（6 个独立子 Agent + Supervisor 仲裁）| 复杂协议 + 通信 | ⭐⭐⭐⭐⭐ | 大 |
| **B. 单 LLM + tool calling + 包装成"多 Agent"对话流** | Claude 4.7 一次推理，把内部 reasoning 展开成多 Agent | ⭐⭐⭐⭐ | 中 |
| C. 单 LLM 多轮调用 | 反复调用扮演不同角色 | ⭐⭐⭐⭐ | 中 |

**初步倾向**：B（演示满分 + 工程量可控，Depix 也是这么干的）
**待决**：团队 AI 工程师拍板

#### 3.2 3D 场景生成走哪条路？

| 选项 | 怎么做 | 质量 | 48h 可行 |
|---|---|---|---|
| A. 完全程序化（bpy 写代码生成几何）| AI 输出尺寸 → 代码画墙画门画窗 | 中（CG 味）| ❌ |
| **B. 模板拼装（预制 20 个房型 + AI 替换家具+风格）** | AI 选模板 → 换 GLB → 改材质 | 高 | ✅ |
| C. text-to-3D 生成 + 拼装 | 调 Tripo/Meshy API | 不稳 | ⚠ |

**初步倾向**：B
**待决**：3D 工程师 + 产品

#### 3.3 渲染：实测速度 vs 承诺时间

实测（M 系 Mac CPU）：
- EEVEE 1024×768: **2.5s**
- Cycles 1024×768 128spp: **130s**
- Cycles 2K 全景 64spp: **172s**

| 选项 | 出图时间 | 质量 | 成本 |
|---|---|---|---|
| 全 EEVEE | 秒级 | 中 | 低 |
| Cycles GPU 云（A100）| 5-15s/张 | 顶 | 中 |
| **EEVEE 预览 + Cycles 终图（后台跑）** | 预览秒级 + 终图等 | 平衡 | 中 |
| **预渲染缓存（hackathon 演示用）** | 0s | 顶 | 0 |

**初步倾向**：实时演示用 EEVEE，hackathon 用预渲染缓存伪装。"90 秒"承诺改"看预览 5 秒，看终图 3 分钟"。
**待决**：产品 + 3D

#### 3.4 法规 RAG 做多深？

| 选项 | 实质 |
|---|---|
| A. 真合规（数字化所有 GB 条款 + 转可检验几何约束）| **不可能**，半年都做不完 |
| **B. 浅合规（家装 5-10 条核心，硬编码 + 几何检查）** | 防火 / 采光 / 疏散 / 老幼适配 |
| C. 假合规（前端 mock）| Demo 能用，真问翻车 |

**初步倾向**：B + 不夸大宣传 "合规检查"
**待决**：产品

### 🟡 技术细节（需拍板但不影响架构）

#### 3.5 "自动化决策智能层"具体实现

| 维度 | 推荐路径 | 原因 |
|---|---|---|
| HDRI 选择 | LLM 决策（语义理解）| "日式日光"→ specific HDR 文件 |
| 三点布光 | 规则表 + LLM 微调 | 物理规则强 |
| 摄像机角度 | **预制 10 种角度库 + LLM 选** | 不让 LLM 生成新角度 |
| 材质参数 | 库里固定 + LLM 选 | 不需生成新材质 |
| 摆放扰动 | 简单数学（±2°/±3cm）| 不需 LLM |
| 后期 LUT | **5-10 个预制 .cube 文件 + LLM 选** | 不需生成 LUT |

**结论**：决策层主要靠 LLM 选择，不靠 LLM 生成。降低不确定性。

#### 3.6 资产库供应

- PolyHaven (CC0 协议，4K HDRI + PBR 材质全免费) ✅
- BlenderKit 付费版 $10/月
- 中/日式风格资产稀缺，需自建 30-50 个关键家具
- **48h MVP**：用 PolyHaven 西式资产先撑 demo

#### 3.7 360° 全景生成

- **建筑**：Blender PANO 相机 → equirectangular JPG → Pannellum 查看 ✅
- **产品**：36 帧 orbit 渲染 → 帧序列 → 前端拖动控制
- **工程标注热点**：Blender 渲染时记录物体世界坐标 → 转 equirectangular UV → Pannellum hotspot（有工程量但可行）

#### 3.8 前后端通信

- WebSocket 推送 Agent 对话流给前端
- 渲染任务 Celery + Redis 队列
- 结果存阿里 OSS / S3

## 4. PoC 实测数据（已验证）

见 `blender-poc/README.md`。核心结论：

- ✅ bpy 程序化建模 28 物体场景：**0.1 秒**
- ✅ EEVEE 1K 出图：**2.5 秒**（适合预览/实时）
- ⚠️ Cycles 1K 128spp 出图：**130 秒**（M 系 Mac CPU，需上 GPU 云）
- ✅ 360° equirectangular 全景渲染跑通
- ⚠️ **默认 Blender 输出仍有"CG 味"**——决策智能层是必须，不是可选
