# 展示技术栈调研：Blender 之外，还有什么路？

> **作者**: @YangJingchi · **日期**: 2026-05-25
> **背景**: 团队内部对"是否把 Blender 当唯一展示层"有疑问。本文做了五条候选路线的实测对比，并给出推荐组合。
> **配套 demo**: 见 `tech/blender-poc/viewer/`（程序化建场景 → GLB → Three.js 网页实时交互）

---

## 1. 问题陈述

讨论的起点是三个具体疑问：

1. AI 在 Blender 里建模的真实能力到底如何？
2. Blender 能导出什么格式的输出？
3. 最终给客户看的展示，**真的应该是 Blender 渲染图**吗？是否存在"更漂亮、更有 wow 感"的路径？

核心担忧：Blender 的强项是 **可控的程序化生成 + 工程图/矢量线稿**，但作为"打动甲方"的展示层，静态图缺乏交互，可能不够炸。

---

## 2. AI 在 Blender 里能做什么

| 能力 | 现状 | 我们用不用 |
|---|---|---|
| LLM 写 `bpy` Python 代码生成几何 | ✅ 稳，PoC 已证（0.1s/28 物体） | **主路径** |
| LLM 选 + 组合预制 GLB 资产 | ✅ 稳，是工业级方案 | **主路径** |
| LLM 直接生成 PBR 材质参数 | ✅ 稳（颜色 / 粗糙度 / 金属度） | 用 |
| LLM 决定光照 / 摄像机 / 后期 | ✅ 稳（决策智能层） | 用 |
| text-to-3D 模型生成（Tripo / Meshy / Rodin / Hunyuan3D）| ⚠️ 质量不稳，拓扑差 | **不作为主路径**，最多备用 |
| LLM 生成自由曲面 / 高细节有机模型 | ❌ 几乎不可能 | 不指望 |

**结论**：BluePrinter 的"AI 建模"应当被精确理解为 **LLM 编排程序化建模 + 资产组合**，而不是"AI 凭空生成模型"。这一点必须在对外宣传时严守，否则承诺兑现不了。

---

## 3. Blender 能导出哪些格式

| 格式 | 用途 | 谁会看到 | 视觉冲击 |
|---|---|---|---|
| **PNG / JPG** (Cycles / EEVEE 渲染) | 静态效果图 | 甲方决策图 | 中–高（取决于决策智能层）|
| **Equirectangular 全景** | Pannellum 网页 360° 浏览 | 甲方"沉浸感"体验 | 中–高 |
| **SVG (Freestyle 线稿)** | 工程图 / 平面布置图 / 立面图 | 施工方 / 监造 | 独特、专业感强 |
| **GLB / glTF** | 网页/AR 实时 3D | 甲方"可拖动 demo" | ⭐⭐⭐ **最炸** |
| **USD / FBX** | 给下游交付（外包施工建模、二次编辑）| 合作方 | — |
| **EXR (HDR)** | 后期调色 | 内部 | — |
| **视频 / 动画** | 漫游 walkthrough | 甲方汇报 | 高 |

**关键发现**：导出 GLB 后用 Three.js 加载——**整个场景文件仅 60.5 KB**，加载 < 100 ms，浏览器内可旋转、缩放、平移。这是用 Blender 静态图实现不了的"活感"。

---

## 4. 五条展示路线的实测对比

| # | 路线 | 实质 | wow | 工程量 | 风险 | 适合阶段 |
|---|---|---|---|---|---|---|
| A | Blender 静态出图 + Pannellum 全景 | 教科书方案 | ⭐⭐⭐ | 1.0× | 低 | 必做基线 |
| **B** | **Blender 几何 → 导 GLB → Three.js 网页实时** | **demo 即所得**| ⭐⭐⭐⭐⭐ | 0.7× | 低 | **48h Hackathon Wow 担当** |
| C | Blender 几何 → ControlNet/SD 风格化 | 颠覆性漂亮 | ⭐⭐⭐⭐⭐ | 1.5× | 高（AI 味、不可控）| 不推荐 demo 用 |
| **D** | **A + B 组合**：缩略图用 Cycles 终图、主交互用 Three.js | 兼顾质量+交互 | ⭐⭐⭐⭐⭐ | 1.5× | 中 | **最终产品形态** |
| **E** | Blender Freestyle SVG 线稿 + 标注 | 给甲方一眼"专业感" | ⭐⭐⭐ | 0.8× | 低 | **PDF 方案书必备** |

各路线的具体感受：

### A. Blender 静态 + Pannellum
- 优点：稳，已验证可行。
- 缺点：甲方第一眼觉得"像截图"。即便 360° 全景能拖，但**总像是预渲染好的素材**——没有"为我实时生成"的感觉。

### B. Blender → GLB → Three.js（本次新增 PoC）
- **场景文件 60 KB**，浏览器 < 100 ms 加载完
- 可拖、可缩、可绕场景任意角度看
- 阴影、PBR 材质、环境光（PMREM）都在浏览器实时算
- 甲方第一感觉：「这是为我现场生成的」——这才是 Hackathon 真正要的 wow
- 缺点：实时渲染不如 Cycles 离线渲染细腻（但已经超过 EEVEE 的中等效果）

### C. Blender 几何 → Stable Diffusion 风格化
- 用 ControlNet 把 Blender 渲染的 depth/normal 喂给 SD → 出"画感强"的图
- **致命问题**：每次出图不一样（甲方说"再做一次"会变样）、有 AI 味（毛发、家具会"长歪")
- 已经在前期讨论中被否决，写在这里只为留存证据。

### D. B + A 组合
- 入口：Three.js 网页（可交互）
- 决策点：右上角"渲染最终效果图"按钮 → 后台 Cycles 跑 1–3 分钟 → 出顶级质量图
- 这是**最终产品形态**，但 48h 内只用 B 即可。

### E. Freestyle SVG 线稿
- Blender 内置的 Freestyle 可以渲染出"建筑设计师手绘"风格的矢量线稿
- 给甲方的 PDF 方案书里：彩图 + 线稿对照 = "我们认真做了设计图，不是只截了渲染图"
- **是 BluePrinter 区别于"AI 出图工具"的关键之一**

---

## 5. 推荐组合

**Hackathon 48h MVP**：用 **B**（主 demo）+ **A**（缩略图）
- Three.js 网页里展示主场景：可拖、可缩
- 旁边贴 4 张 Cycles 离线渲染的 1024×768 PNG（不同角度的"效果图"）
- 360° 全景按需展示

**正式产品（V1）**：用 **D + E**
- 网页前端：Three.js 实时交互
- 一键导出：Cycles 高清效果图（4 张）+ Freestyle SVG 线稿（平面 + 立面）+ Equirectangular 全景 + 自动排版 PDF 方案书

---

## 6. 本次 PoC 验证数据

| 项目 | 结果 |
|---|---|
| Blender 程序化建场景（28 物体）| 0.46s |
| 导出 GLB | 0.25s |
| **GLB 文件大小** | **60.5 KB** |
| Three.js 浏览器加载耗时 | < 100ms |
| 浏览器实时帧率 | 60 FPS（M 系 Mac，Safari/Chrome）|
| 网页技术栈依赖 | 仅 three.js（CDN，无打包）|

**对比**：同一场景，Cycles 离线渲染 1024×768 需要 130 秒，而 Three.js 网页实时渲染同样的场景每帧只要 16 ms。**这就是为什么 demo 必须走实时路线，而不是静态出图。**
